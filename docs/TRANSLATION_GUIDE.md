# Руководство по созданию языкового пакета

Это руководство объясняет процесс добавления нового языка в OpenCode Russian Language Pack.

## Обзор архитектуры

Плагин использует формат JSON для хранения переводов. Каждый язык — отдельный файл в `i18n/locales/<code>.json`.

Система работает по принципу **fallback**: если перевода нет, показывается английский оригинал. Плагин не ломает интерфейс при неполном словаре.

## Шаг 1. Создание JSON-файла

Создайте файл:

```text
i18n/locales/<code>.json
```

Где `<code>` — код языка по BCP 47 (например: `es`, `fr`, `de`, `ja`, `ko`, `pt`, `zh-Hans`, `zh-Hant`).

Возьмите структуру из `i18n/locales/ru.json` или используйте шаблон `examples/locale-template.json`.

## Шаг 2. Получение списка команд

Запустите инструмент извлечения команд из исходников OpenCode:

```bash
# Укажите путь к исходникам OpenCode (должен содержать packages/tui/src)
bun tools/extract-commands.ts --src D:\path\to\opencode-src --skeleton <code>
```

Инструмент:
- Сканирует исходный код OpenCode на предмет команд
- Добавляет в ваш файл пустые заготовки (`""`) для всех найденных команд
- Сохраняет динамические варианты заголовков (например, "Hide sidebar" / "Show sidebar")

### Альтернатива: runtime dump

Если OpenCode уже запущен с плагином, он автоматически пишет дамп команд в:
```
~/.config/opencode/i18n/commands-dump.json
```

Инструмент извлечения объединяет статический анализ исходников с runtime dump для максимальной полноты.

## Шаг 3. Создание шаблона

После запуска `--skeleton` в вашем файле появятся записи вида:

```json
"session.new": {
  "titles": {
    "New session": "",
    "Create a new session": ""
  },
  "description": ""
}
```

Пустые строки — это маркеры отсутствующего перевода. При загрузке они игнорируются, и используется fallback.

## Шаг 4. Перевод

Заполните все пустые строки русскими переводами.

### Примеры перевода

| English | Русский |
|---|---|
| New session | Новая сессия |
| Switch agent | Сменить агента |
| Open settings | Открыть настройки |
| Search files | Поиск файлов |
| Toggle sidebar | Показать/скрыть боковую панель |
| Copy to clipboard | Скопировать в буфер обмена |
| Cancel | Отмена |
| Confirm | Подтвердить |
| Loading... | Загрузка... |

### Особенности

1. **Динамические заголовки** — одна команда может иметь несколько английских вариантов:
   ```json
   "session.sidebar.toggle": {
     "titles": {
       "Hide sidebar": "Скрыть боковую панель",
       "Show sidebar": "Показать боковую панель",
       "Toggle sidebar": "Переключить боковую панель"
     }
   }
   ```

2. **Описание** — одно на команду, применяется ко всем вариантам заголовка.

3. **Группы** — переводятся отдельно:
   ```json
   "groups": {
     "Agent": "Агент",
     "Session": "Сессия"
   }
   ```

4. **Slash-команды** — переводятся описания:
   ```json
   "slash_commands": {
     "/share": "Поделиться текущей сессией"
   }
   ```

## Шаг 5. Проверка

Запустите валидацию полноты словаря:

```bash
bun tools/validate-locale.ts --locale <code>
```

Инструмент сообщит:
- Количество найденных команд
- Количество переведённых команд
- Количество непереведённых строк
- Количество устаревших ключей (команд больше нет в OpenCode)
- Количество отсутствующих динамических вариантов

### Пример вывода

```
=== Locale Validation: es ===
Locale name: Español

Commands:     180 / 197 translated
  Titles:       250 / 326 translated (76 missing, 0 empty)
  Descriptions: 30 / 37 translated (7 missing, 0 empty)
Groups:       20 / 25 translated (5 missing, 0 empty)
Slash cmds:   45 / 52 translated (7 missing, 0 empty)

✗ 90 missing translations
```

Стремитесь к 100% переводу для команд первого уровня.

## Шаг 6. Подключение

1. Добавьте код языка в `i18n/config.json`:
   ```json
   {
     "defaultLocale": "ru",
     "locales": ["en", "ru", "es"]
   }
   ```

2. Добавьте сообщения для UI плагина в `src/index.ts` (блок `MESSAGES`).

3. Пересоберите/переустановите плагин.

4. После перезапуска OpenCode запустите `/i18n` — новый язык должен появиться в списке.

## Автоматизация обновлений

При выходе новой версии OpenCode:

```bash
# 1. Обновите исходники OpenCode
# 2. Запустите извлечение с обновлением скелета
bun tools/extract-commands.ts --src D:\path\to\opencode-src --skeleton <code>

# 3. Переведите новые строки
# 4. Проверьте
bun tools/validate-locale.ts --locale <code>
bun test
```

Инструмент `extract-commands.ts` автоматически:
- Добавит новые команды
- Добавит новые варианты заголовков к существующим командам
- Пометит устаревшие ключи (в отчёте, не удаляет автоматически)

## Сравнение с базовым языком

Для проверки полноты относительно эталонного языка (например, китайского):

```bash
bun tools/compare-locales.ts --base zh-Hans --target <code>
```

Покажет:
- Команды, которых нет в вашем языке
- Отличия в вариантах заголовков
- Отличия в группах и slash-командах

## Добавление языка в конфигурацию плагина

В `src/index.ts` добавьте блок сообщений для нового языка:

```typescript
const MESSAGES: Record<string, Messages> = {
  en: { ... },
  ru: { ... },
  es: {
    unset: "no establecido",
    noLocalesInline: "Idiomas disponibles: no se encontraron paquetes",
    // ... все поля из интерфейса Messages
  },
}
```

В `src/tui.tsx` команда `/i18n` автоматически подхватит новый язык из конфига.

## Публикация

1. Убедитесь, что все тесты проходят
2. Обновите версию в `package.json`
3. Опубликуйте в npm:
   ```bash
   npm publish
   ```
4. Тегируйте релиз в Git

## Советы по качеству

1. **Контекст** — перед переводом откройте OpenCode и найдите команду в интерфейсе
2. **Краткость** — терминальный интерфейс требует коротких строк
3. **Единообразие** — используйте один и тот же термин для одного понятия
4. **Тестирование** — проверяйте отображение в реальном TUI
5. **Fallback** — не бойтесь оставлять пустые строки, fallback работает надёжно

## Пример полного цикла для испанского

```bash
# 1. Создать файл из шаблона
cp examples/locale-template.json i18n/locales/es.json

# 2. Извлечь команды и создать скелет
bun tools/extract-commands.ts --src D:\opencode-src --skeleton es

# 3. Отредактировать es.json — перевести все пустые строки

# 4. Проверить
bun tools/validate-locale.ts --locale es

# 5. Добавить в config.json
# 6. Добавить сообщения в src/index.ts

# 7. Тесты
bun test

# 8. Готово!
```
