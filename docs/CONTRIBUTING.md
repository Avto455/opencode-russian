# Руководство по участию в разработке

Спасибо за интерес к улучшению русской локализации OpenCode!

## Как сообщать о проблемах

### Ошибки перевода
Если вы нашли неточный или неправильный перевод:

1. Откройте Issue на GitHub
2. Укажите:
   - ID команды (например, `session.new`)
   - Текущий перевод
   - Предлагаемый перевод
   - Контекст, где видно неверное отображение

### Отсутствующие переводы
Если какая-то команда не переведена:

1. Запустите проверку: `bun tools/validate-locale.ts --locale ru`
2. Откройте Issue со списком отсутствующих ключей

## Как предлагать изменения

### Pull Request

1. Форкните репозиторий
2. Создайте ветку: `git checkout -b fix/translation-session-new`
3. Внесите изменения в `i18n/locales/ru.json`
4. Запустите тесты: `bun test`
5. Запустите валидацию: `bun tools/validate-locale.ts --locale ru`
6. Создайте Pull Request

### Правила оформления PR

- Один PR — одна логическая группа изменений (например, все команды сессий)
- В заголовке PR укажите область: `fix: translate session commands`, `feat: add diff commands`
- Опишите, что именно изменено и почему

## Терминология

Обязательно используйте утверждённый словарь терминов:

| Английский | Русский |
|------------|---------|
| Agent | Агент |
| Session | Сессия |
| Context | Контекст |
| Provider | Провайдер |
| Model | Модель |
| Prompt | Промпт |
| Tool | Инструмент |
| Tool call | Вызов инструмента |
| Token | Токен |
| Usage | Использование |
| Cost | Стоимость |
| Permission | Разрешение |
| Approval | Подтверждение |
| Configuration | Конфигурация |
| Working directory | Рабочая директория |

### Общие правила перевода

1. **Не переводите** идентификаторы команд, аргументы, пути к файлам, URL, программный код
2. **Сохраняйте** динамические переменные (например, `{file}`, `{count}`)
3. **Используйте** единообразную терминологию (см. таблицу выше)
4. **Коротко** и технически грамотно — для терминального интерфейса
5. **Избегайте** машинного дословного перевода, если он ухудшает понимание
6. **При отсутствии перевода** оставляйте пустую строку — сработает fallback на английский

## Обновление словаря при новой версии OpenCode

Когда выходит новая версия OpenCode:

```bash
# 1. Обновите исходники OpenCode (или укажите путь к новому чекауту)
# 2. Запустите извлечение команд:
bun tools/extract-commands.ts --src D:\path\to\opencode-src --skeleton ru

# 3. Проверьте что добавилось:
bun tools/validate-locale.ts --locale ru

# 4. Переведите новые пустые строки в ru.json
# 5. Запустите тесты:
bun test
```

## Структура файла перевода

Файл `i18n/locales/ru.json` имеет структуру:

```json
{
  "name": "Русский",
  "language_picker": {
    "question": "Выберите язык интерфейса",
    "option_descriptions": {
      "en": "Вернуться к оригинальному английскому интерфейсу",
      "ru": "Переключиться на русский интерфейс"
    }
  },
  "commands": {
    "command.id": {
      "titles": {
        "English title": "Русский перевод",
        "Another English variant": "Другой русский вариант"
      },
      "description": "Описание команды"
    }
  },
  "groups": {
    "English Group": "Русская группа"
  },
  "slash_commands": {
    "/command": "Описание slash-команды"
  }
}
```

### Ключи команд

- Используйте стабильные ID команд (`session.new`, `agent.list`), а не случайный порядок
- Один ID может иметь несколько английских вариантов заголовка (динамические заголовки)
- Описание применяется ко всем вариантам заголовка одной команды

### Группы

- Ключ — английское название группы
- Значение — русский перевод

### Slash-команды

- Ключ — имя slash-команды со слешем (`/new`, `/agents`)
- Значение — краткое описание на русском

## Тестирование

Перед отправкой PR обязательно запустите:

```bash
# Валидация полноты перевода
bun tools/validate-locale.ts --locale ru

# Автоматические тесты
bun test

# Проверка типов (если настроено)
bunx tsc --noEmit
```

## Кодовый стиль

- JSON с отступом в 2 пробела
- Ключи в алфавитном порядке (поддерживается инструментами)
- Нет завершающих запятых
- Кодировка UTF-8
